# Runtime ownership — 2.0.0-rc.2

`FunTimeEventsAPI.builder().…buildLease()` — рекомендуемый API для независимого
consumer-мода. Результат — `net.funtimeevents.api.RuntimeLease`, `AutoCloseable`.
Публичные методы получения данных остаются прежними. Минимальный компилируемый
пример находится в `examples/consumer` и проверяется для каждого target.

## Правила

- Один runtime на процесс. Полная конфигурация всех владельцев должна совпадать,
  включая ключ, URL, User-Agent, режимы, интервалы, флаги и log level.
  Конфликт отклоняется без вывода конфиденциальных значений.
- Каждый buildLease создаёт отдельный handle. Он принадлежит объекту конкретного
  поколения runtime; старый handle не влияет на новый runtime.
- close идемпотентен, в том числе при конкурентном закрытии одного handle.
  Последний lease закрывает runtime, если нет legacy pin.
- Legacy build() возвращает прежний FunTimeEventsAPI и устанавливает lifetime pin.
  Повторный равный build() возвращает тот же объект. Pin не является счётчиком.
- Legacy shutdown() бросает IllegalStateException, если есть активные leases.
  Он ничего не отключает при отказе. Без leases shutdown снимает legacy pin и
  освобождает runtime. Повторный shutdown без runtime ничего не делает.
- CLIENT_STOPPING освобождает ресурсы независимо от pin и handles, запрещает новые
  acquire и завершает ожидающие операции ошибкой. Закрытие старых handles безопасно.
- JOIN/DISCONNECT относятся к игровой сессии. Lease держат в течение lifetime
  consumer-мода; не закрывайте его на DISCONNECT.

Два независимых legacy build() нельзя безопасно учитывать: API не сообщает,
какой вызывающий завершил использование. Их shutdown должен координировать один
host-мод. Для независимого владения обоим потребителям нужны leases.

## Потоки

Инициализация, конфликты, счётчик leases и shutdown сериализованы на Minecraft
client thread. Фоновый вызов синхронно передаёт операцию в его executor без
удержания ownership lock во время ожидания. Не делайте client-thread join/get
worker, который вызывает build/buildLease/close/shutdown: это обычный цикл ожидания
UI executor. Создание Builder и его мутация остаются обязанностью одного вызывающего;
готовая конфигурация копируется перед передачей на клиентский поток.

Runtime публикуется после полной инициализации. При ошибке очищаются все созданные
ресурсы; ошибки cleanup добавляются suppressed к исходной ошибке. Каждая очистка
пытается закрыть все caches/соединения, даже если отдельное закрытие не удалось.
Одна Fabric bridge остаётся зарегистрированной после остановки и принимает новое
поколение. Ни acquire, ни reconnect не добавляют вторую подписку.

Синхронные статические методы получения данных сохраняют прежнюю семантику общего
runtime. Lease не создаёт отдельный backend-клиент и не делает разные ключи совместимыми.
